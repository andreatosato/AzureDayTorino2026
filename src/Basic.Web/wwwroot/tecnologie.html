BASIC / LA MAPPA DELLE TECNOLOGIE

Tool. Agenti. Procedure.

MCP collega strumenti e dati. A2A collega agenti. Una Skill insegna all'agente come svolgere un compito.

Tre concetti, non tre alternative equivalenti

MCP e A2A sono protocolli di comunicazione. Una Skill è un pacchetto di istruzioni e risorse: non è un protocollo di rete e non è un agente autonomo.

In questa BASIC, Basic.Web è il punto di ingresso centrale: la scelta dell'utente avvia uno dei tre percorsi con uno switch. Non c'è un orchestratore intelligente che pianifica o sceglie le tecnologie.

01 / MODEL CONTEXT PROTOCOL

MCP: uso uno strumento

L'agente è il client: scopre i tool disponibili e il modello decide quale chiamare. Il server espone la funzionalità e ne restituisce il risultato. Una chiamata al tool non è una delega a un secondo agente.

Esempio: “Che tempo fa a Torino?” → get_weather → pioggia, 14 °C.

MCP non richiede che il server abbia un modello. In generale supporta anche risorse e prompt; questa demo espone un solo tool.

02 / AGENT-TO-AGENT

A2A: delego a uno specialista

Il client legge la Agent Card per conoscere nome, capacità ed endpoint. Invia una richiesta allo specialista, che svolge il compito con la propria logica e i propri tool. Il client riceve il risultato senza dover conoscere tutti i dettagli interni.

Esempio: “Dammi due consigli per visitare Torino.” → lo specialista legge il meteo e prepara i consigli.

A2A è la comunicazione tra agenti, non la condivisione automatica del loro contesto. Qui ci sono chiamate al modello sia nel Web sia nel processo remoto.

03 / AGENT SKILLS

Skill: carico una procedura

Una Skill fornisce istruzioni riutilizzabili e risorse di supporto. Il provider rende visibili nome e descrizione; l'agente carica il contenuto pertinente e lo segue usando i tool a disposizione. Caricare una Skill non crea un secondo agente.

Esempio: “Prepara un briefing per visitare Torino.” → carica city-briefing → raccoglie i tre dati → produce il briefing.

Qui nessuna rete, MCP o A2A per caricare la Skill e chiamare i suoi tool. Il modello resta su Foundry. Una Skill può includere risorse o script, ma questa demo non esegue script.

Possono lavorare insieme?

Sì: una Skill può descrivere una procedura che usa tool MCP; uno specialista A2A può usare a sua volta tool MCP o Skill. I tre concetti sono complementari.
